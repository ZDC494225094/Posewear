# 生成失败与网络连接排查

## 2026-10-31 本机故障

- 11:40、11:42、11:44 创建的三个作品任务均在连接渠道时失败，数据库原始错误为 `NETWORK / UND_ERR_CONNECT_TIMEOUT`，每个任务尝试三次后退回全部点数。
- 这不是模型审核拒绝、点数不足或图片参数被拒绝。没有获得 HTTP 响应，不能据此判断渠道正在限流或模型繁忙。
- 排查时使用实际渠道 Key 连续三次调用免费的 `/v1/models`，均返回 HTTP 200，且包含配置的模型。该结果仅证明当时连通且 Key 有效，不能代替付费图片生成验收，也不能说明先前断连的外部原因。
- 后续复查仍出现过一次 30 秒连接超时，之后又能快速连接，说明链路存在间歇性故障；延长连接时限只能缓解，不能保证外部网络可用。DNS 检查也观察到 CDN 节点变化，未修改系统 DNS、hosts、代理或把渠道固定到某个 IP。

## 代码调整

- Node fetch 默认的约 10 秒连接时限不受全局 240 秒请求超时控制。图片请求现在使用独立的连接时限，默认 30 秒，可在「后台 → AI 渠道 → 编辑 → 连接超时」设置为 1–120 秒；完整请求仍受原有请求超时约束。
- 明确区分连接超时、一般网络故障、等待响应超时、HTTP 限流/服务繁忙。最终失败不再把全部临时故障都改写为“繁忙”。
- 响应正文读取中断也归入具体网络故障，并在管理员任务详情保留诊断信息。参考图、模型参数、计费、既有重试次数和内容安全校验不变；未增加底层透明重试。
- 新增 `undici` 运行时依赖；本机已安装。其他部署环境需要先运行 `npm ci`，再启动服务。

## 启用与验证

1. 等正在生成的任务结束，再在原启动终端按 `Ctrl+C`，运行 `npm start`。浏览器强制刷新后可看到新设置。仅刷新网页不会更新服务端网络处理。
2. 「后台 → AI 渠道 → 测试连接」调用免费的 `/v1/models`。该检查通过不代表图片接口一定能生成。
3. 如仍失败，先看管理员任务详情的 `errorDetail`，以及渠道最近错误；不要反复点击“试生成一张”。连接超时应继续检查本机到渠道的 DNS、网络、代理和渠道服务状态。
4. 已失败任务不自动重跑，不修改历史错误，也不重新扣点。需要真实出图验证时，应由用户确认后另发一个任务。

`npm test` 中的故障回归使用本地接口、隔离数据库和模拟超时，不消耗真实模型额度。
